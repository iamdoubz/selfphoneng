# 10 — Local AI

Owner, 2026-10-21: AI features that run on the PBX server (or the local network) only. No call
audio, transcript or prompt leaves it.

## 1. Endpoints

Three OpenAI-style APIs, set in Settings → AI (`ai.llm`, `ai.stt`, `ai.tts`), with `AI_*` env
values as the starting defaults (`services/settings.ts`):

| Setting | API used | Reference server |
|---|---|---|
| `ai.llm` {url, model} | `POST chat/completions` | Ollama (`/v1`) |
| `ai.stt` {url, model} | `POST audio/transcriptions` (multipart, `response_format=json`) | Speaches (Whisper) |
| `ai.tts` {url, model, voice} | `POST audio/speech` (`response_format=wav`) | Speaches (Kokoro) |

`ai/client.ts` refuses any address that isn't `localhost` or an IP in 127/8, 10/8, 172.16/12,
192.168/16, ::1, fc00::/7 or fe80::/10, written as an IP: no DNS, so no lookup can send data
elsewhere. Checked on save and before every request. Redirects are refused. CGNAT (100.64/10,
Tailscale) is refused too: it may cross the internet.

`POST /api/ai/test {kind, endpoint}` (admin) sends one tiny request (a chat, a second of silence,
one sentence of speech) with the values in the form, saved or not.

`deploy/ai/compose.yml` is its own stack: Speaches on 127.0.0.1:8000 with the GPU, and an
optional Ollama.

## 2. Voicemail transcripts (`ai.voicemailTranscripts`)

When a new message is indexed (04 §5.6), before the webhook, live event and email, the WAV goes to
`ai.stt` (180 s timeout). The text is stored in `voicemail_messages.transcript`, added to the
email ("What they said (automatic, may have mistakes)") and shown on the voicemail page. A failure
is logged and the message goes out without it.

   person.
